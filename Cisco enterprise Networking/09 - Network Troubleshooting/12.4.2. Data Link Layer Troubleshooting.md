# [[Data Link Layer Troubleshooting|Resolución de Problemas en la Capa de Enlace de Datos]]
De igual manera que en el nivel físico, en la [[Data Link Layer|Capa de Enlace de Datos]] (Capa 2) se manifiestan algunos de los errores y fallas más comunes dentro de la infraestructura local. Mientras que la Capa 1 se encarga de los bits y la electricidad, la Capa 2 gestiona el direccionamiento físico (MAC), la delimitación de tramas y el control de acceso al medio, por lo que un error en este nivel interrumpe la comunicación local de inmediato.

 
| Tipo de Error / Falla Lógica | Protocolo o Componente | Síntoma Operativo / Acción de Diagnóstico |
| :--- | :--- | :--- |
| **Errores de encapsulación (Mismatch)** | HDLC / PPP / Ethernet | La interfaz física muestra un estado activo (Up), pero el protocolo de línea permanece caído (Down). Validar que ambos extremos hablen el mismo protocolo. |
| **Errores lógicos de tramas (CRC / Runts)** | Contadores de interfaz del Switch | Acumulación de tramas corruptas, demasiado pequeñas (Runts) o gigantes. Suele indicar problemas de dúplex (Duplex Mismatch) o ruido en el cable. |
| **Tormentas de Broadcast (Bucles de red)** | [[STP\|Spanning Tree Protocol (STP)]] | Uso de CPU al 100% en los switches, LEDs parpadeando de forma masiva y pérdida total de conectividad local. Revisar prioridades del puente raíz (Root Bridge). |
| **Fallas en enlaces troncales (Trunks)** | Enlaces 802.1Q / [[VLAN]] | Pérdida de comunicación entre switches de diferentes áreas o alertas de "Native VLAN Mismatch". Diagnosticar con `show interfaces trunk`. |

> **Consejo de diagnóstico:** Cuando utilices comandos de verificación como `show interfaces`, pon especial atención a la primera línea del reporte. Si visualizas el estado *«Interface is Up, line protocol is Down»*, descarta inmediatamente problemas de cables físicos (Capa 1) y enfócate por completo en esta capa (Capa 2), revisando fallas de encapsulación, seguridad de puerto (Port Security) o configuraciones de Keepalives desalineadas.
