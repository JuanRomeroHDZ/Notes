# [[Syslog|Servidor Syslog como Herramienta de Resolución de Problemas]]
Syslog es un protocolo estándar utilizado por dispositivos de infraestructura conocidos como **Syslog Clients**, los cuales permiten enviar mensajes de texto plano (text-based messages) hacia una dirección IP determinada para su almacenamiento, centralización y análisis posterior. 

Generalmente, este protocolo sigue el estándar **[[RFC 5424]]**, el cual define con precisión la estructura, los campos y el formato de los mensajes enviados, facilitando la recopilación masiva y la administración de registros dentro de una infraestructura multi-marca.

Se recomienda ampliamente activar el registro de mensajes de error en los dispositivos y configurar sus diferentes medios o destinos de visualización, ya que permiten identificar fallas en tiempo real, monitorear comportamientos anómalos y construir líneas base de diagnóstico.

 
| Medio de Registro (Logging Destination) | Ubicación del Almacenamiento | Propósito Técnico / Caso de Uso en Redes |
| :--- | :--- | :--- |
| **Console (Consola)** | Puerto físico de consola (Línea CON 0). | Visualización directa y en tiempo real de eventos críticos durante sesiones de diagnóstico local. |
| **Terminal (Líneas VTY)** | Sesiones remotas activas (SSH o Telnet). | Supervisión de alertas de forma remota mientras un ingeniero ejecuta comandos o mantenimientos. |
| **Buffered (Memoria de logueo)** | Memoria RAM interna del dispositivo. | Almacenamiento local temporal útil para revisar un historial de eventos pasados sin depender de la red. |
| **Syslog Server** | Servidor externo dedicado en la red. | Centralización permanente de registros de múltiples equipos para auditorías y correlación de eventos. |
| **[[SNMP]] Trap** | Sistema de Monitoreo de Red externo (NMS). | Envío de alertas asíncronas e inmediatas para notificar fallas críticas a consolas de monitoreo globales. |

## Niveles de Severidad en [[Cisco IOS]]
Los mensajes generados por el proceso de logging de Cisco IOS se rigen por una escala jerárquica de ocho niveles de severidad (numerados del 0 al 7). Comprender esta clasificación es vital para aplicar filtros correctos tanto en la memoria local del equipo como en el servidor de almacenamiento centralizado, evitando saturar los discos con alertas innecesarias:

> **Buenas prácticas de administración:** Activar el reenvío de logs a un servidor Syslog externo es mandatorio en redes corporativas. Si un router o switch sufre un fallo eléctrico crítico, un kernel panic o un reinicio inesperado, los datos guardados en la memoria RAM (`buffered memory`) se perderán para siempre, impidiendo analizar la causa raíz del colapso. Un servidor Syslog remoto garantiza que el último mensaje de auxilio del hardware quede guardado a salvo fuera del equipo afectado.
