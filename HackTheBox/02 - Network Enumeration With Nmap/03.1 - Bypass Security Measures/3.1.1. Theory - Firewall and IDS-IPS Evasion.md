## Firewalls
Bueno, un firewall es una medida de seguridad que no permite las conexiones no autorizadas de redes externas/internas. Cualquier firewall está basado en componentes de software/hardware que monitrean el trafico que pasa a través de ellos y decide como reaccionar basado en las reglas previamente configuradas.
El sistema está diseñado para prevenir conexiones no queridas que podrían ser peligrosas.
## IDS/IPS
Este es interesante, nos permite hacer monitoreo activo y pasivo, en el caso de que se necesite poner reglas, pues se puede realizar. Como el firewall, *the intrusion detection system (IDS)* e *intrusion prevention system (IPS)* son herramientas de software. El IDS nos permite escanear la red para detectar potenciales ataques, analizarlos y reportarlos. El IPS complementa al IDS, esto para tomar medidas de seguridad ante un posible ataque. ### Determine Firewalls and Their Rules
Pues no recordaba pero nos dice que normalmente cuando un puerto aparece con el status *filtered* es muy probable de que haya sido un firewall con reglas especificas el que haya causado que se comportara de alguna manera.  normalmente se manejan dos estados, los cuales serían; *dropped, rejected*, como se puede observar, normalmente el estado rejected necesita explicitamente que haya una respuesta del otro lado. Mientras que el estado de dropped son paquetes ignorados y normalmente no hay respuesta del otro lado.
Normalmente el estado de rejected puede contener diferentes RST flags para el protocolo TCP, mientras que el protocolo ICMP puede contener diferentes tipos de errores, algunos serían;
* Net Unreachable
- Net Prohibited
- Host Unreachable
- Host Prohibited
- Port Unreachable
- Proto Unreachable
El escaneo TCP ACK de nmap (-sA) es un metodo mucho más fuerte para pasar filtros de firewalls, sistemas IDS e IPS que el regular -sS. Okay, es interesante, porque según recuerdo -sS no hace la conexión TCP ACK como si lo haría -sT, en este caso, supongo que sería más lento el escaneo utilizando -sA. De hecho si lo explican, Regular SYN (-sS) o TCP connect (-sT) solamente envian un paquete TCP solamente con el flag ACK. Cuando un puerto está abierto o cerrado, el host responde con una flag RST. 
## SYN-Scan
Realmente no dice nada, solo utiliza el siguiente comando:
```nmap
sudo nmap -p21,22,25 -sS -Pn -n --disable-arp-ping --packet-trace [IP]
```
Puedo explicar un poco; realiza un escaneo a los puertos 21,22,25 utilizando -sS el cual solamente envia el paquete pero no espera respuesta, luego utiliza -Pn para no hacer peticiones de ICMP, esto normalmente se hace cuando se sabe que el host está vivo, también utiliza -n porque está utilizando la IP y no el nombre del dominio. Utiliza --packet-trace para ver la trasabilidad de los paquetes enviados, aunque no se que hace --disable-arp-ping aunque supongo que desabilitaría el protocolo ICMP o las peticiones ICMP a la tabla arp (dudo de esto).

## Detect IDS/IPS
Interesante, nos habla de que los IDS/IPS son sistemas más complejos que un firewall al ser sistemas pasivos, ya que se encargan de realizar el monitoreo del trafico. Los sistemas IDS examinan toda las conexiones entre los hosts Si el IDS encuentra paquetes que contienen el contenido o especificaciones previamente configuradas/definidas, se le notifica al encargado/administrador para que tome las medidas necesarias.
Los sistemas IPS, como su nombre lo dice, previene ataques automaticamente. Es esencial conocer que un IDS y un IPS son completamente diferentes, y que un IPS sirve como complemento para un IDS.
