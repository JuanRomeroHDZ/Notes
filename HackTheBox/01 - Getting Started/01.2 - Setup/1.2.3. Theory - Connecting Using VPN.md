# [[Connecting Using VPN|Conexión Mediante VPN (Connecting Using VPN)]]
A **Virtual Private Network ([[VPN]])** creates an encrypted tunnel across a public or untrusted network (such as the Internet), allowing a remote host to communicate with resources inside a private network as if it were physically connected to the local switch.

![[Pasted image 20260824172446.png]]

VPNs establish secure, authenticated communication channels, making remote corporate work possible (e.g., an employee securely accessing internal servers from home or while connected to public Wi-Fi).

---
## VPN Architecture Comparison
Depending on implementation requirements and administrative control, VPN architectures fall into two primary categories:

| Architecture Type                           | Client Requirement                                           | Layer & Protocol                                                     | Primary Use Case                                                                   |
| :------------------------------------------ | :----------------------------------------------------------- | :------------------------------------------------------------------- | :--------------------------------------------------------------------------------- |
| **[[Client-Based VPN]]**                    | Dedicated software agent (e.g., [[WireGuard]], [[OpenVPN]]). | Layers 3 & 4 (UDP/TCP tunnel encapsulating full OS network traffic). | Full administrative network access, lab connectivity (HTB), routing subnets.       |
| **[[SSL VPN\|SSL / TLS VPN (Clientless)]]** | Web browser only (HTTPS portal).                             | Layer 7 / Transport ([[TLS]] over Port 443).                         | Granular access to specific internal web applications, portal-based remote access. |

---
### 1. Client-Based VPN
Requires installing dedicated software on the endpoint. The client handles encryption, handshake negotiation, routing table updates, and virtual interface creation (e.g., `tun0`, `wg0`).
```mermaid
flowchart LR
    Client[Cliente / Endpoint] -->|Túnel Cifrado| VPN[Servidor / Gateway VPN]
    VPN --> RedInterna[Red Interna Destino]
````
- **Examples:** [[WireGuard]], [[OpenVPN]], Cisco AnyConnect (full client), IPsec / IKEv2 clients.
- **Behavior:** Encapsulates all or specifically routed IP packets at the operating system level, routing raw Layer 3 traffic into the remote network.
### 2. SSL / TLS VPN (Clientless Portal)
Eliminates the need for local client installation by leveraging the native [[TLS]] capabilities of modern web browsers.
```mermaid
flowchart LR
    U[Usuario]
    B[Navegador / Cliente VPN]
    S[Servidor SSL VPN]
    R[Red interna]
    A[Aplicaciones internas]

    U --> B
    B -->|HTTPS / TLS| S
    S -->|Túnel VPN| R
    R --> A
```
- **Behavior:** The user accesses a secure web portal. The VPN appliance acts as a reverse proxy/gateway translating web interactions into internal requests without modifying the client's OS routing table.
## Security Context: Privacy vs. Anonymity
Connecting through a VPN secures the communication channel against local eavesdropping (e.g., man-in-the-middle attacks on open coffee shop networks) and hides traffic contents from the local Internet Service Provider (ISP).
> **Crucial Distinction:** **A VPN does NOT equal total anonymity.**
> - While a VPN masks the user's real IP address from external websites and encrypts in-transit data, the VPN gateway operator still maintains logs and session metadata. Application-layer tracking, browser fingerprinting, and account authentications persist regardless of the VPN tunnel.    
## Connecting to Hostile Testing Environments (HTB / Proving Grounds)
When connecting via VPN to penetration testing platforms like **Hack The Box (HTB)**, the network environment must be treated as **actively hostile** 
1. **Multi-Tenant Risk:** All connected players share the same virtual subnet (`10.10.x.x` / `10.12.x.x`). Any attacker on that network can scan, probe, and attempt to exploit your connected IP address.
2. **[[Network Isolation|Isolation via Virtual Machines]]:** Always establish testing VPN connections from inside an isolated Virtual Machine (via KVM/QEMU), never directly from the bare-metal host.
3. **Firewalling the Tunnel:** Maintain strict ingress firewall rules (e.g., `ufw` or `iptables`) on the `tun0` interface, allowing only necessary reverse shell listener ports and blocking unrequested incoming scans.
