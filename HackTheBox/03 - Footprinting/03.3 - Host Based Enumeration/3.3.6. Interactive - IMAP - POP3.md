Okay, a diferencia de SMTP, IMAP y POP3 son protocolos encargados de recibir los emails.
*Internet Message Access Protocol (IMAP)*, es posible acceder a los emails desde un servidor de correos. A diferencia de *Post Office Protocol (POP3)*, IMAP permite la administración de los emails en linea directamente en el servidor y admite estructuras de carpetas. De este modo, es un protocolo de red para la administración de emails en un servidor remoto. El protocolo es cliente-servidor y permite la sincronización de un cliente email local con el buzón en el servidor, otorgando una especie de sistema de archivos de red para los emails, permitiento una sincronización sin problemas entre varios clientes independientes. Por otra parte POP3 no tiene la misma funcinoalidad como IMAP y solo provee las funciones de listar, recuperar y eliminar emails en el servidor de correo electrónico. Por lo tanto, se debe utilizar protocolos como IMAP para funcionalidades adicionales como buzones de correo jerárquicos directamente en el servidor de correo, acceso a múltiples buzones durante una sesión u preselección de emails. Al final ambos son dependientes, uno permite el acceso a los emails y el otro otorga mayores funcionalidades. El cliente accede a estas estructuras de manera remota y puede crear copias locales. Incluso entre varios clientes, esto resulta en una base de datos uniforme. Los emails permanecen en el servidor hasta que se eliminan. IMAP se basa en texto y cuenta con funciones avanzadas, como la posibilidad de consultar los emails directamente en el servidor. También es posible para muchos usuarios acceder al servidor email de manera simultanea. Sin una conexión activa al servidor, administrar los emails es imposible. Sin embargo, algunos clientes ofrecen un modo offline con una copia del buzón. El cliente sincroniza todos los cambios locales cuando la conexión se reestablece.
El cliente establece la conexión al servidor por el puerto 143. Para la comunicación, utiliza comandos basados en el formato *ASCII*. Muchos de los comandos pueden ser enviados consecutivamente sin esperar confirmación del servidor. 
Posteriormente, el servidor puede asignar confirmaciones a cada comando mediante los identificadores que se envían junto con ellos. Inmediatamente después de establecer la conexión, el usuario se autentica en el servidor con su nombre de usuario y contraseña. El acceso al buzón deseado solo es posible tras una autenticación exitosa.
SMTP usualmente es utilizado para enviar emails. Al copiar los emails enviados en una carpeta IMAP, todos los clientes tienen acceso a todos los emails dentro de esa carpeta (emails enviados), independientemente del PC desde el que fue se enviaron.
Otra ventaja de Internet Message Access Protocol (IMAP) es la posibilidad de crear carpetas personales y estructuras de carpetas en el buzón de correo. Esta ventaja hace el buzón más claro y facil de administrar. Sin embargo, el requerimiento del almacenamiento del espacio en el servidor incrementa. 
Sin medidas adicionales, IMAP funciona sin cifrar y transmite comandos, emails o nombres de usuario y contraseñas en texto plano. Muchos de los servidores emails requieren establecer una sesión IMAP cifrada para garantizar una mayor seguridad en el tráfico de emails y evitar el acceso no autorizado a los buzones. Generalmente se utiliza SSL/TLS para este fin. Dependiendo del método y la implementación, la conexión cifrada utiliza el puerto estándar 143 o un puerto alternativo como el 993.
## Default Configuration
No nos dice mucho de la configuración por default, pero nos dice que podemos descargar los servicios de envio y transferencia smtp - imap/pop3.
### IMAP Commands
Basicamente nos dice que hagamos pruebas para adentrarnos en la sintaxis.

|**Command**|**Description**|
|---|---|
|`1 LOGIN username password`|User's login.|
|`1 LIST "" *`|Lists all directories.|
|`1 CREATE "INBOX"`|Creates a mailbox with a specified name.|
|`1 DELETE "INBOX"`|Deletes a mailbox.|
|`1 RENAME "ToRead" "Important"`|Renames a mailbox.|
|`1 LSUB "" *`|Returns a subset of names from the set of names that the User has declared as being `active` or `subscribed`.|
|`1 SELECT INBOX`|Selects a mailbox so that messages in the mailbox can be accessed.|
|`1 UNSELECT INBOX`|Exits the selected mailbox.|
|`1 FETCH <ID> all`|Retrieves data associated with a message in the mailbox.|
|`1 CLOSE`|Removes all messages with the `Deleted` flag set.|
|`1 LOGOUT`|Closes the connection with the IMAP server.|

Algunas empresas utilizan sus propios servidores de correos, tal vez por privacidad. Uno de ellos como dije antes, es mantener la privacidad.
