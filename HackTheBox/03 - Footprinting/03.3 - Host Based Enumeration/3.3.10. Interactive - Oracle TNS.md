Es lo mismo que todas las bases de datos pero desarrollado por Oracle, su nombre en teoría es: *Oracle Transparent Network Substrate (TNS)* el cual es un protocolo de comuniacción que facilita la comunicación entre las bases de datos de Oracle y aplicaciones sobre la red. inicialmente se integró primero a la suit como parte de *Oracle Net Services*, Transparent Network Substrate soporta varios protocolos de red entre las bases de datos y aplicaciones de clientes, tales como IPX/SPX y TransportControlProtocol/InternetProtocol (TCP/IP). Se ha convertido en la solución favorita para administrar bases de datos grandes y complejas en el sector de la salud, financiera y la industria minorista. Además, su mecanismo de cifrado garantiza la seguridad de los datos transmitidos, lo que la convierte en una solución ideal para entornos empresariales donde la seguridad de los datos es primordial. Una pequeña investigación otorga que PostgreSQL es el mejor en relación costo/beneficio.
Con el tiempo, Transparent Network Substrate ha sido actualizado para que soporte tecnologías más actuales como  lo es IPv6 y la encriptación TLS/SSL, el cual lo hace más adecuado para los siguientes propósitos:

| Name Resolution | Connection Management | Load Balancing | Security |
| --------------- | --------------------- | -------------- | -------- |
Además, permite el cifrado entre la comunicación cliente-servidor mediante una capa adicional de seguridad sobre la capa del protocolo TCP/IP. Este caracteristica ayuda a la seguridad de la arquitectura de la base de datos de permitir a los atacantes el acceso no autorizado comprometiendo los datos en el trafico de la red. Además, provee herramientas y capacidades avanzadas para administradores y desarrolladores ya que ofrece monitoreo y analisis de rendimiento, reporte de errores y capacidades de registro e informes, gestión de la carga de trabajo y tolerancia a fallos a traves de los servicios de la base de datos.
## Default Configuration
Normalmente Transparent Network Substrate corre utilizando el protocolo TCP en el puerto 1521, sin embargo, este puede ser cambiado. El TNS listener puede ser configurado para soportar varios protocolos de red incluyendo los que mencionamos anteriormente TCP/IP, IPX/SPX y AppleTalk. Los listener pueden tambien soportar varias interfaces de red y escuchar direcciones de IP especificas o todas las interfaces de red disponibles. Por default Oracle Transparent Network Substrate puede ser administrado remotamente en Oracle 8i/9i pero no en Oracle 10g/11g. 
> [!Note] Ni pta idea de que sea 8/9i y 10/11g.
Indagando un poco más, la i es por internet (un protocolo) y g es de grid

La configuración por default de los listener de Oracle TNS tambien trae consigo algunas cuantas caracteristicas de seguridad, por ejemplo, solo aceptará conexiones de hosts autorizados  y que hagan uso de autenticación básica utilizando combinación de nombres de host, direcciones IP, nombres de usuario y contraseñas.
Oracle Transparent Network Substrate a veces es utilizado con otros servicios de Oracle, como Oracle DBSNMP, Oracle Databases, Oracle Application Server, Oracle Enterprise Manager, Oracle Fusion Middleware, web servers y muchos más. Se han realizado cambios para la configuración predeterminada de Oracle, por ejemplo, Oracle 9 tiene una contraseña por default *CHANGE_ON_INSTALL*, Oracle 10 no tiene contraseña configurada. La contraseña de Oracle DBSNMP tambien tiene una contraseña por default, *dbsnmp*. Otro ejemplo podría ser que muchas organizaciones continuan utilizando el servicio *finger* junto con Oracle, lo que puede poner en riesgo el servicio de Oracle y hacerlo vulnerable cuando tenemos el conocimiento necesario de un directorio principal.

Cada base de datos o servicio tiene una entrada unica en el archivo *tnsnames.ora*, el cual contiene la información de los clientes para que se conecten al servicio. La entrada consiste de un nombre para el servicio, la ubicación de red para el servicio, y la base de datos o nombre de servicio que el cliente debería utilizar cuando se quiere conectar al servicio, por ejemplo, un archivo *tnsname.ora*.
```tnsname
ORCL =
  (DESCRIPTION =
    (ADDRESS_LIST =
      (ADDRESS = (PROTOCOL = TCP)(HOST = 10.129.11.102)(PORT = 1521))
    )
    (CONNECT_DATA =
      (SERVER = DEDICATED)
      (SERVICE_NAME = orcl)
    )
  )
```
### Tnsnames.ora
En el archivo anterior vemos un servicio llamado *orcl* el cual está escuchando en el puerto *1521* y está utilizando el protocolo *TCP* en la dirección IP *10.129.11.102*. Los clientes deberían utilizar el nombre *orcl* para conectarse al servicio. Sin embargo, el archivo *tnsnames.ora* puede contener muchas entradas de este tipo para diferentes bases de datos y servicios. Estas entradas también pueden incluir información adicional, como detalles de autenticación, configuraciones de agrupación de conexiones y configuraciones de balanceo de carga.

```listener.ora
SID_LIST_LISTENER =

LISTENER =

    (DESCRIPTION =

      (ADDRESS = (PROTOCOL = IPC)(KEY = EXTPROC1521))
    )

ADR_BASE_LISTENER = C:\oracle
```
El software Oracle Net Services del lado del cliente utiliza el archivo *tnsnames.ora* para resolver los nombres de los servicios y direcciones de red, mientras que el proceso de escucha utiliza el archivo *listener.ora* para determinar los servicios a los que debe escuchar y el comportamiento.
Las bases de datos Oracle pueden estar protegidos utilizando la denominada lista de exclusión *PL/SQL* (PlsqlExclusionList). Es un texto creado por el usuario que debe ubicarse en el directorio $ORACLE_HOME/sqldeveloper, y contiene el nombre o tipo de los paquetes *Pl/SQL* que deberían ser excluidos de la ejecución. Una vez que el *PL/SQL* es creado, puede ser cargado dentro de las instancias de las bases de datos. Sirve como una lista negra que no puede acceder a través del *Oracle Application Server*.
