MySQL es un sistema de administración para base de datos relacionales de modelo de codigo abierto desarrollado y apoyado por Oracle. Como sabemos, una base de datos es una colección de datos organizados que facilitan su uso. Bueno, una base de datos tiene la capacidad de procesar cantidades enormes de datos. Dentro de la base ed datos, el almacenamiento de datos se realiza de manera que ocupe el menos espacio posible. La base de datos es controlada utilizando el lenguaje SQL. MySQL funcione principalmente como cliente-servidor, lo cual consiste en un servidor MySQL y en uno o varios clientes. Los datos se almacenan en tablas con diferentes columnas, filas y tipos de datos, esas bases de datos a menudo se exportan o son respaldadas como un simple archivo *.sql*, por ejemplol; *wordpress.sql*
## MySQL Clients
Los clientes de MySQL pueden recuperar y editar los datos utilizando consultas estructuradas al motor de la base de datos. Ingresar, eliminar, modificar y recuperar/reparar/recobrar los datos se hace utilizando el lenguaje SQL. Por lo tanto, MySQL es adecuado para administrar bases de datos de muchas maneras diferentes mientras los clientes pueden enviar multiples consultas simultaneamente. Dependiendo de la configuración de la base de datos, se puede acceder de manera local o desde internet.
Uno de los mejores ejemplos de uso de bases de datos es el *CMS WordPress* que almacena todos los posts creados, nombres de usuarios, contraseñas, etc. Todo en su propia base de datos, el cual es solamente accesible desde el interior (local).
## MySQL Databases
MySQL es ideal para aplicaciones como sitios web dinámicos, donde la sintaxis eficiente y la velocidad alta de respuesta son esenciales. A veces se combina con Linux, PHP y el servidor web Apache, también llamado *LAMP (Linux-Apache-MySQL-PHP)* o cuando se utiliza Nginx se le conoce como *LEMP*. En un alojamiento web con base de datos MySQL, esto sirve como una instancia central donde se almacena el contenido requerido por los scripts PHP. Entre ellos se encuentran:

| Headers                 | Texts            | Meta tags         | Forms      |
| ----------------------- | ---------------- | ----------------- | ---------- |
| Customers               | Usernames        | Administrators    | Moderators |
| Email addresses         | User information | Permissions       | Passwords  |
| External/Internal links | Links to Files   | Specific contents | Values     |
Muchas veces por desconocimiento se realiza el almacenamiento de contraseñas o datos sensibles sin encriptar (texto plano), por lo cual muchas de estas veces cuando se logra acceder al sistema, la base de datos provee toda la información sensible al atacante. Se recomiendan cifrados, metodos de encriptación para mejorar la seguridad de los sistemas y proteger la información.
## MySQL Commands
Una base de datos traduce los comandos internamente a codigo ejecutable y realiza la acción requerida. La aplicación web informa al usuario si ocurre un error durante el rpceso, el cual muchos de ellos pueden ser provocados por ataques de *SQL injection*. A veces los errores de descripción contienen información importante y confirma entre otras cosas que la aplicación web interactua con la base de datos de manera diferente a la cual los desarrolladores prevenian.
Como sabemos, el cliente se comunica con el servidor realizando consultas, una vez que los datos son procesados, los datos pueden ser extraidos de una tabla o registro, esto resulta en inicios de sesión, funciones, etc. Bueno, los comandos se basan en 4 pilares que son Create, Read, Update y Delete, pero obviamente hay varios más enmedio de cada uno de ellos, por otra parte, esto tambien se puede modificar a nivel de tablas. Además, SQL tambien puede cambiar la estructuras de las tablas, crearlas, eliminar relaciones entre cada una de ellas, indexarlas, administrar usuarios, etc.
*MariaDB* muchas veces es utilizado con MySQL, haciendo que sea una bifurcación del código original de MySQL. Al final esto resultó de esa manera porque el encargado de desarrollar MySQL dejó la compañia *MySQL AB* despues de que lo contrataran en Oracle este encargado creó una base de datos open source conocida como MariaDB que estaba basado en MySQL.
## Default Configuration
Podemos instalar el servidor de MySQL
```shell
sudo apt install install mysql-server -y
```
Para ver la configuración por default que contiene el servidor podemos buscar en la ruta:
```shell
cat /etc/mysql/mysql.conf.d/mysqld.cnf | grep -v "#" | sed -r '/^\s*$/d'
```
## Dangerous Settings
Hay muchas configuraciones que pueden producir errores en el servicio de MySQL. Para determinar que opciones se pueden configurar en el servidor. Las principales opciones relevantes para la seguridad son:

|**Settings**|**Description**|
|---|---|
|`user`|Sets which user the MySQL service will run as.|
|`password`|Sets the password for the MySQL user.|
|`admin_address`|The IP address on which to listen for TCP/IP connections on the administrative network interface.|
|`debug`|This variable indicates the current debugging settings|
|`sql_warnings`|This variable controls whether single-row INSERT statements produce an information string if warnings occur.|
|`secure_file_priv`|This variable is used to limit the effect of data import and export operations.|
> [!WARNING] Las configuraciones de ***User*, *Password*** y ***Admin_address*** son relevantes porque las entradas se realizan en texto plano

Las opciones *debug* y *sql_warnings* proporcionan información detallada en caso de errores, la cual es esencial para el administrador pero no debería ser visible para otros usuarios.
## Footprinting the Service
Podemos hacer uso de varios scripts que tiene nmap, lo cual la verdad lo vuelve bastante util pero tambien lo vuelve muy ruidoso al realizar el escaneo.
```nmap
sudo nmap -sV -sC -p3306 --min-rate=5000 --script=mysql* -vvv [IP]
```
No es necesario explicar cada uno de los apartados del comando utilizado, son realmente parametros sencillos que facilitan la obtención de la información.
