el *Simple Mail Transfer Protocol (SMTP)*  es un protocolo para enviar emails en una red IP. Se puede utilizar entre un cliente de correo electronico y un servidor de correo saliente o entre dos servidores SMTP. SMTP se suele combinar con los protocolos IMAP o POP3, que permiten recibir y enviar emails.
En principio, es un protocolo basado en cliente - servidor, a pesar de que SMTP puede ser utilizado entre un cliente y un servidor y entre dos servidores SMTP. En este caso, un servidor efectivamente actua como cliente.
Por defecto el servidor SMTP acepta peticiones en el puerto 25. Sin embargo, servidores más actuales, también utilizan otros puertos como el puerto TCP 587. Este puerto se utiliza para recibir emails  de usuarios/servidores autenticados, normalmente mediante el comando *STARTTLS* para cambiar la conexión de texto plano existente a una conexión cifrada. Los datos de la autenticación es protegida y ya no es visible en texto plano sobre la red. Al inicio de la conexión, la autenticación ocurre cuando el cliente confirma su identidad con un usuario y una contraseña. Entonces el email puede ser transmitido. Para ello, el cliente envia al servidor las direcciones del remitente y del destinatario, el contenido del email y otra información y parametros. Despues de que el email ha sido transmitido, la conexión vuelve a terminar. El servidor de email comienza a enviar los emails a otro servidor SMTP. 
SMTP  funciona sin cifrado y transmite todos los comandos, datos e información de autenticación en texto plano. Para evitar la lectura no autorizada de datos, SMTP se utiliza junto con el cifrado SSL/TLS. En determinadas circunstancias, un servidor utiliza un puerto distinto al puerto estandar 25 para la conexión cifrada, por ejemplo, el puerto TCP 465.
Una función esencial de un servidor SMTP es prevenir el spam utlizando mecanismos de autenticación que permiten solamente usuarios autorizados a enviar emails. Por este proposito, la mayoria de los servidores SMTP modernos soportan la extensión de protocolo *ESMTP* con *SMTP-Auth*. Despues de enviar su email, el cliente SMTP tambien conocido como *Mail User Agent (MUA)*, lo convierte en una cabecera y cuerpo, y los envía al servidor SMTP. Este servidor cuenta con un *Mail Transfer Agent (MTA)* o agente de transferencia de correo, el software que permite enviar y recibir correos electronicos. El MTA comprueba el tamaño y la presencia de spam en el correo electrónico y lo almacena. Para aliviar la carga del MTA, a veces interviene un  *Mail Submission Agent (MSA)* que verifica la valides, es decir, el origen del email. Este MSA tambien se denomina *Relay Server* o servidor de retransmisión. 
Es importante ya que, el ataque de retransmisión abierta (*Open Relay Attack*) puede llevarse a cabo en muchos servidores SMTP mal configurados.
Al llegar al servidor SMTP de destino, los paquetes de datos se vuelven a ensamblar para formar un email completo. Desde allí, el agente de entrega de correo (*Mail Delivery Agent*) lo transfiere al buzón del destinatario.
