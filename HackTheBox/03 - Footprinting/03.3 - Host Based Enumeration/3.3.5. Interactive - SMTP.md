El *Simple Mail Transfer Protocol (SMTP)*  es un protocolo para enviar emails en una red IP. Se puede utilizar entre un cliente de correo electronico y un servidor de correo saliente o entre dos servidores SMTP. SMTP se suele combinar con los protocolos IMAP o POP3, que permiten recibir y enviar emails.
En principio, es un protocolo basado en cliente - servidor, a pesar de que SMTP puede ser utilizado entre un cliente y un servidor y entre dos servidores SMTP. En este caso, un servidor efectivamente actua como cliente.
Por defecto el servidor SMTP acepta peticiones en el puerto 25. Sin embargo, servidores más actuales, también utilizan otros puertos como el puerto TCP 587. Este puerto se utiliza para recibir emails  de usuarios/servidores autenticados, normalmente mediante el comando *STARTTLS* para cambiar la conexión de texto plano existente a una conexión cifrada. Los datos de la autenticación es protegida y ya no es visible en texto plano sobre la red. Al inicio de la conexión, la autenticación ocurre cuando el cliente confirma su identidad con un usuario y una contraseña. Entonces el email puede ser transmitido. Para ello, el cliente envia al servidor las direcciones del remitente y del destinatario, el contenido del email y otra información y parametros. Despues de que el email ha sido transmitido, la conexión vuelve a terminar. El servidor de email comienza a enviar los emails a otro servidor SMTP. 
SMTP  funciona sin cifrado y transmite todos los comandos, datos e información de autenticación en texto plano. Para evitar la lectura no autorizada de datos, SMTP se utiliza junto con el cifrado SSL/TLS. En determinadas circunstancias, un servidor utiliza un puerto distinto al puerto estandar 25 para la conexión cifrada, por ejemplo, el puerto TCP 465.
Una función esencial de un servidor SMTP es prevenir el spam utlizando mecanismos de autenticación que permiten solamente usuarios autorizados a enviar emails. Por este proposito, la mayoria de los servidores SMTP modernos soportan la extensión de protocolo *ESMTP* con *SMTP-Auth*. Despues de enviar su email, el cliente SMTP tambien conocido como *Mail User Agent (MUA)*, lo convierte en una cabecera y cuerpo, y los envía al servidor SMTP. Este servidor cuenta con un *Mail Transfer Agent (MTA)* o agente de transferencia de correo, el software que permite enviar y recibir correos electronicos. El MTA comprueba el tamaño y la presencia de spam en el correo electrónico y lo almacena. Para aliviar la carga del MTA, a veces interviene un  *Mail Submission Agent (MSA)* que verifica la valides, es decir, el origen del email. Este MSA tambien se denomina *Relay Server* o servidor de retransmisión. 
Es importante ya que, el ataque de retransmisión abierta (*Open Relay Attack*) puede llevarse a cabo en muchos servidores SMTP mal configurados.
Al llegar al servidor SMTP de destino, los paquetes de datos se vuelven a ensamblar para formar un email completo. Desde allí, el agente de entrega de correo (*Mail Delivery Agent*) lo transfiere al buzón del destinatario.

| Client (`MUA`) | `➞` | Submission Agent (`MSA`) | `➞` | Open Relay (`MTA`) | `➞` | Mail Delivery Agent (`MDA`) | `➞` | Mailbox (`POP3`/`IMAP`) |
| -------------- | --- | ------------------------ | --- | ------------------ | --- | --------------------------- | --- | ----------------------- |
Pero el protocolo SMTP tiene dos grandes desventajas:
1. La primera es que el envío de un correo electrónico mediante SMTP no devuelve una configuración de entrega útil. Si bien, las especificaciones del protocolo contemplan este tipo de notificación, su formato no está definido por defecto. por lo que generalmente solo se devuelve un mensaje de error en inglés, que incluye la cabecera del mensaje no entregado.
2. Los usuarios no se autentican al establecer una conexión, por lo que el remitente del email no es fiable. Como resultado, los servidores SMTP abiertos se utilizan con frecuencia para enviar spam masivo. Los remitentes utilizan direcciones de correo electrónico falsas y arbitrarias para evitar ser rastreados (*mail spoofing/suplantación de identidad*). Actualmente, se emplean diversas ténicas de seguridad para prevenir el uso indebido de los servidores SMTP, por ejemplo, los emails sospechosos se rechazan o se envían a cuarentena (*spam folder*). Entre los responsables de esto se encuentran el protocolo de identificación *DimainKeys (DKIM)* y el *Sender Policy Framework (SPF)*.
Para este proposito, se ha desarrollado una extensión llamada *Extended Simple Mail Transfer Protocol (ESMTP)*. Cuando la gente habla sobre SMTP en general, usualmente se refieren a ESMTP. ESMTP utiliza TLS, lo cual se realiza después del comando *EHLO* mediante el envio de *STARTTLS*. Esto inicializa la conexión SMTP protegida por SSL, y a partir de este momento, toda la conexión queda cifrada y por lo tanto, es más o menos segurida. Ahora tambien se puede utilizar de forma segura la extensión *AUTH PLAIN* para la autenticación.
## Default Configuration
Cada servidor SMTP puede ser configurado de muchas formas, al igual que todos los demás servicios. Sin embargo, hay diferencias porque el servidor SMTP es el unico responsable de enviar y reenviar emails.
### Default Configuration

El envio y la comunicación tambien se realizan mediante comandos especiales que hacen que el servidor SMTP haga lo que el usuario requiere.

|**Command**|**Description**|
|---|---|
|`AUTH PLAIN`|AUTH is a service extension used to authenticate the client.|
|`HELO`|The client logs in with its computer name and thus starts the session.|
|`MAIL FROM`|The client names the email sender.|
|`RCPT TO`|The client names the email recipient.|
|`DATA`|The client initiates the transmission of the email.|
|`RSET`|The client aborts the initiated transmission but keeps the connection between client and server.|
|`VRFY`|The client checks if a mailbox is available for message transfer.|
|`EXPN`|The client also checks if a mailbox is available for messaging with this command.|
|`NOOP`|The client requests a response from the server to prevent disconnection due to time-out.|
|`QUIT`|The client terminates the session.|
Para interactuar con el puerto 25/TCP 465, podemos utilizar la herramienta *Telnet*, esto para iniciar la conexión con dicho servidor. La inicialización de la sesión se realiza con los comandos *HELO, EHLO*

El header del email contiene una gran cantidad de información relevante. Entre otros datos, proporciona información sobre el remitente y el destinatario, la hora de envio y llegada, las estaciones por las que pasó el  email durante su trayecto, el contenido y el formato del mensaje, asi como la identidad del remitente y del destinatario.
Parte de la información es obligatoria, como podría ser el remitente y la fecha de creación del correo. Otra información es opcional, sin embargo, la cabecera no contiene información necesaria para la entrega técnica. Se transmite como parte del protocolo de transmisión. Tanto el remitente como el destinatario pueden acceder a la cabecera, aunque no sea visible a simple vista. La estructura de la cabecera está definida en el *RFC 5322*
