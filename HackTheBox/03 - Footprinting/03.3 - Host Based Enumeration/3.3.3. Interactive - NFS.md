NFS significa Network File System, es muy parecido a lo que hace SMB, este fue creado por Sun de Microsystems. Al ser similares, tienen propositos similares, ya que este se encarga de que se pueda acceder a archivos del sistema sobre internet, como si estuvieran de manera local.
Sin embargo, NFS utiliza un protocolo completamente diferente. NFS puede y es utilizado entre sistemas Linux y sistemas Unix, esto significa que no se puede conectar directamente con servidores SMB. NFS es un estándar de internet que rige los procedimiento en un sistema de archivos distribuido. Como bien sabemos, existen varias versiones de NFS, el protocolo NFS version 3.0 (*NFSv3*), ha sido usado por años, autentica la computadora del cliente, estos cambia con la versión 4.0 (*NFSv4*). Al igual que en protocolo SMB de Windows, el usuario debe de autenticarse.

|**Version**|**Features**|
|---|---|
|`NFSv2`|It is older but is supported by many systems and was initially operated entirely over UDP.|
|`NFSv3`|It has more features, including variable file size and better error reporting, but is not fully compatible with NFSv2 clients.|
|`NFSv4`|It includes Kerberos, works through firewalls and on the Internet, no longer requires portmappers, supports ACLs, applies state-based operations, and provides performance improvements and high security. It is also the first version to have a stateful protocol.|
La versión de NFS 4.1 (*RFC 8881*) tiene como objetivo proveer soporte al protocolo para aprovechar las implementaciones de servidores en clúster, incluyendo la habilidad de proveer acceso paralelo escalable a archivos distribuidos a traves de multiples servidores (*pNFS* extension). *NFSv4.1* incluye un mecanismo de troncalización de sesiones.  una de las ventajas de *NFSv4* sobre sus antecesores, es que solamente uno, UDP o TCP del puerto ***2049*** es utilizado para corre el servicio, el cual simplifica el uso del protocolo a traves de firewalls.
NFS está basado en *Open Network Computing Remote Procedure Call (ONC-RPC/SUN-RPC)*,  el cual es un protocolo expuesto el puerto TCP y UDP 111, el cual utiliza *External Data Representation (XDR)* para el intercambio de datos de los sistemas independientes. El protocolo NFS no tiene mecanismo de autenticación o autorización, en lugar de eso, la autenticación es completamente trasladada a las opciones del protocolo RPC. La autorización es entragada desde la información del sistema de archivos disponibles. En este proceso, el servidor es responsable de traducir la información del usuario del cliente al formato del sistema de archivos y convertir los detalles de la autorización correspondiente a la sintaxis requerida de UNIX con la mayor precisión posible.
La via más comun de autenticación es mediante UNIX UID/GID y *group memberships*, razón por la cual es muy probable que esta sintaxis se aplique al protocolo NFS. Un problema es que el cliente y el servidor no necesariamente tienen que tener las mismas asignaciones de UID/GID para los usuarios y los grupos, y el servidor no necesita hacer nada más. El servidor no puede realizar comprobaciones adicionales. Por este motivo, NFS solo debe utilizarse con este método de autenticación en redes de confianza.
## Default Configuration
Dice que no es tan dificil de configurar ya que no tiene tantas configuraciones como SMB o FTP. El archivo en la ruta */etc/exports* contiene una tabla de archivos de sistema en un servidor NFS accesible por los clientes. La tabla *NFS Exports* muestra que opciones acepta y eso nos indica que opciones estan disponible para nosotros.
### Exports File
El archivo por default *exports* tambien contiene algunos ejemplos de configuración de archivos NFS. Primero se especifica la carpeta y se pone a disposición de los demás, y luego los permisos que obtendrán en este archivo NFS son conectados a un host o a una subred. Finalmente, las opciones adicionales pueden ser agregados al host o a la subred.

|**Option**|**Description**|
|---|---|
|`rw`|Read and write permissions.|
|`ro`|Read only permissions.|
|`sync`|Synchronous data transfer. (A bit slower)|
|`async`|Asynchronous data transfer. (A bit faster)|
|`secure`|Ports above 1024 will not be used.|
|`insecure`|Ports above 1024 will be used.|
|`no_subtree_check`|This option disables the checking of subdirectory trees.|
|`root_squash`|Assigns all permissions to files of root UID/GID 0 to the UID/GID of anonymous, which prevents `root` from accessing files on an NFS mount.|

## Footprinting the Service
Ya que utiliza los puertos 111 y 2049, resulta esencial realizar la investigación basada en esos puertos.
### Nmap
Se recomienda utilizar nmap y los scripts que este contiene dentro para realizar la investigación.
### Show Available NFS Shares
Podemos utilizar el comando *showmount -e [IP]* para ver los servidores NFS montados en un sistema.
### Mounting NFS Share
Según lo que entendí es que podemos levantar un servidor NFS, nos dan el siguiente comando:
```nfs
sudo mount -t nfs 10.129.14.128:/ ./target-NFS/ -o nolock
```
- Sudo: Ejecuta con privilegios de administrador
- mount: Monta un sistema de archivos
- -t ngs: Especifica que utilizará NFS
- [IP]:/: IP del servidor y */* como ruta exportada del servidor
- ./target-NFS/: Directorio local donde se accederá a los archivos
- -o nolock: desactiva el bloqueo de archivos mediante NLM.
Allí tendremos la oportunidad de acceder a los derechos, nombres de usuario y grupos a los que pertenecen los archivos mostrados y visibles. Porque una vez que tenemos los usuarios, nombres de grupo, UIDs y GUIDs, podemos crearlos en nuestro sistema y adaptarlos a NFS para ver y modificar archivos.
