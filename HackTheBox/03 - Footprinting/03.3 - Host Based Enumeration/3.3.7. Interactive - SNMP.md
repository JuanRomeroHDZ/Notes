*Simple Network Management Protocol (SNMP)* fue creado para monitorear dispositivos de red, además, este protocolo también permite configurar tareas y cambiar configuraciones remotamente. El hardware compatible con SNMP incluye enrutadores, conmutadores, servidores, dispositivos IoT y muchos otros dispositivos que también puede consultarse y controlarse mediante este protocolo estándar. Por lo tanto, se trata de un protocolo para la monitorización y gestión de dispositivos de red. Además, mediante este estándar se pueden gestionar tareas de configuracion y realizar ajustes de forma remota. La versión actual es SNMPv3, el cual incrementa la seguridad de SNMP en particular, pero también la complejidad del uso de este protocolo. Además para el puro intercambio de información, SNMP transmite comandos de control mediante agentes que funcionan a traves del puerto UDP 161. El cliente puede configurar valores especificos en el dispositivo y cambiar opciones y configuraciones con algunos comandos. Mientras en la comunicación clasica siempre es el cliente quien activamente requiere información del servidor, SNMP tambien es capaz de usar algo llamado *Traps* que utiliza el protocolo UDP sobre el puerto 162. Son paquetes enviados desde el servidor SNMP para el cliente sin que fueran explicitamente requeridas. Si un dispositivo está configurado correctamente, se envía un *Trap* SNMP al cliente cuando se produce un evento especifico en el servidor. Para que el cliente y el servidor SNMP intermcabien los valores correspondientes, los objetos SNMP disponibles deben tener direcciones únicas conocidas por ambas partes. Este mecanismo de direccionamiento es un requisito indispoensable para la transmisión exitosa de datos y la monitorización de la red mediante SNMP.
### MIB
Para garantizar que el acceso SNMP funcione entre fabricantes y con diferentes combinaciones cliente-servidor, se creó *Management Information Base (MIB)* o Base de Información de Gestión. El Management Information Base es un formato independiente para almacenar información de dispositivos. Un archivo MIB es un archivo de texto que enumera todos los objetos SNMP consultables de un dispositivo en una jerarquía de árbol estandarizada. Contiene al menos un *Object Identifier (OID)/ Identificador de Objeto* que, además de la dirección única y el nombre necesario, tambien proporciona información sobre el tipo. Los derechos de acceso y una descripción del objeto correspondiente.
Los archivos MIB están escritos en formato de texto ASCII basado en *Abstract Syntax Notation One (ASN.1)/ Sintaxis Abstracta Uno (ASN.1)*. Los archivos MIB no contienen datos, sino que explican dónde encontrar qué información y cómo se presenta, qué valores devuelve para el Object Identifier (OID) especifico o qué tipo de datos se utiliza.
### OID
Un OID representa un nodo en un espacio de nombres jerárquico. Cada nodo se identifica de forma única mediante una secuencia de números, lo que permite determinar su posición en el árbol. Entre más grande sea la cadena, más especifica es la información. Muchos de los nodos en el arbol OID no contienen nada excepto referencias a los que se encuentran debajo de ellos. Los OIDs consisten de números enteros que estan usualmente concatenados mediante la notación de puntos.
## SNMPv1
La versión #1 del *Simple Network Management Protocol* es utilizado para la administración de redes y el monitoreo. Simple Network Management Protocolv1 es la primer versión del protocolo y continua utilizandose en muchas empresas pequeñas. Soporta la recuperación de información de los dispositivos de red, permite la configuración de dispositivos y provee *traps*, los cuales son notificaciones de eventos. Sin embargo, el Simple Network Management Protocolv1 no tiene mecanismo de autenticación incorporado, significa que cualquiera que esté en la red puede leer y modifirar los datos de red. Otro defecto es que Simple Network Management Protocolv1 no soporta encriptación, lo que significa que los datos son enviados en texto plato.
> [!DANGER] **Poco seguro** pero muy utilizado en empresas pequeñas.
## SNMPv2
SNMPv2 existia en diferentes versiones, actualmente hoy en día prevalece la versión v2c, la extensión *c* significa *SNMP basado en la comunidad*. En lo que respecta a la seguridad, SNMPv2 esta al par con SNMPv1 y ha sido ampliado con funcionalidades adicionales basado en partes desde que ya no se utiliza. Sin embargo, hay un problema muy grande con la ejecución inicial del protocolo SNMP y es que la comunidad provee seguridad y solo es transmitido en texto plano, lo que significa que tampoco tiene encriptación incluida.
## SNPMv3
En esta versión se incorporó la seguridad como *autenticación* utilizando usuarios, contraseñas y para la transmisión se utilizó la encriptación via *pre-shared key* para los datos. Sin embargo, la complejidad incrementó y ahora provee más opciones de configuración que la versión *v2c*
## Community Strings
Los *comminuty strings* pueden considerarse contraseñas que se utilizan para determinar si la información solicitada puede ser vista o no. Es importante notar que muchas orgnizaciones continuan utilizando SNMPv2 y la transición a SNMPv3 puede ser muy complejo, pero los servicios deben seguir activos. Esto causa gran preocupación entre administradores y crea algunos problemas que se quieren evitar. La falta de conocimiento sobre como se puede obtener la información y cómo la utilizamos nosotros, como atacantes, hace que el enfoque de los administradores parezca inexplicable. Al mismo tiempo, la falta de encriptación de los datos es un problema, porque cada vez que la comunidad los manda por la red, estos pueden ser interceptados y leidos.
## Default Configuration
Algunas configuraciones peligrosas de Simple Network Management Protocol pueden ser:

| Settings                                         | Description                                                                           |
| ------------------------------------------------ | ------------------------------------------------------------------------------------- |
| `rwuser noauth`                                  | Provides access to the full OID tree without authentication.                          |
| `rwcommunity <community string> <IPv4 address>`  | Provides access to the full OID tree regardless of where the requests were sent from. |
| `rwcommunity6 <community string> <IPv6 address>` | Same access as with `rwcommunity` with the difference of using IPv6.                  |
